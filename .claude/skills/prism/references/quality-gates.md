# Quality Gates

Use this to run the Executive Review (workflow step 19) and to sanity-check your own draft before showing it. Be a demanding senior partner, not a supportive colleague.

> **The load-bearing rule:** A beautiful artifact is still weak if it does not increase the probability of the desired audience outcome.

## The 14 gates (pass / fail, with a one-line reason)

1. **Objective clear** — is the true audience outcome stated as a specific verb + audience, not a topic?
2. **Audience specific** — named roles and the actual decision-maker, not "leadership"?
3. **Decision/action explicit** — is the ask unambiguous (who does what, how big)?
4. **States defined** — are current and desired audience states both present and concrete?
5. **Belief shifts clear** — stop-believing / start-believing pairs identified?
6. **Confidence & trust gaps addressed** — does it move the audience past "understands" to "confident enough to act"?
7. **Objections addressed** — are the real reasons for no/delay pre-empted?
8. **Evidence sufficient** — is there proof this audience will trust, for each key claim?
9. **Evidence gaps honest** — are missing proofs named, not papered over?
10. **Artifact justified** — is the chosen format defended against the default the user asked for?
11. **Narrative logical** — does each part follow from the last; would a skeptic track it?
12. **Concise** — is anything present that does not raise outcome probability?
13. **Executive-readable fast** — can a busy senior reader get the recommendation in under a minute?
14. **Raises outcome probability** — the meta-gate. If the honest answer is "not really," the artifact fails regardless of polish.

Any failed gate must appear in the review with a specific fix.

## The 10 scored dimensions (1–5)

Score each, then average for the verdict. Anchors:

| Dimension | 1 (weak) | 3 (usable) | 5 (executive_ready) |
|---|---|---|---|
| Objective clarity | topic only ("about AI") | outcome stated but fuzzy | precise verb + audience + ask |
| Audience specificity | "leadership" | named group | named decider, their lens known |
| Decision explicitness | no ask | ask present, size vague | exact ask, owner, timing |
| Objection coverage | none | top objection noted | top 3 objections pre-empted with responses |
| Evidence strength | assertions only | some proof, mixed fit | proof matched to what this audience trusts |
| Narrative logic | list of facts | mostly follows | tight, skeptic-proof spine |
| Medium fit | wrong artifact | acceptable artifact | artifact clearly optimal for the outcome |
| Concision | bloated | some filler | every element earns its place |
| Executive readability | must hunt for the point | point findable | point + ask land in the first lines |
| Audience-transformation strength | no state change designed | states named, path thin | clear, credible path from current → desired state |

## Verdict rules

Average of the 10 scores:

- `< 2.5` → **weak** — do not show this; rebuild.
- `2.5 – < 3.5` → **usable** — shows internally with fixes; not leadership-ready.
- `3.5 – < 4.5` → **strong** — leadership-ready after named fixes.
- `≥ 4.5` → **executive_ready** — ship it.

## Weak vs strong (worked contrasts)

**Objective**
- Weak: "Inform leadership about AI." *(topic, no outcome, no decider)*
- Strong: "Get the ExCo to approve a £250k, 90-day AI adoption pilot in claims processing." *(verb + audience + specific ask)*

**Decision ask**
- Weak: "We recommend considering next steps for AI." *(no one can act on this)*
- Strong: "Decision requested today: sponsor the pilot and name an accountable exec by Friday." *(owner, timing, binary)*

**Evidence**
- Weak: "AI is transforming every industry." *(unfalsifiable, untrusted, generic)*
- Strong: "Two competitors cut claims cycle time ~30% with the same approach (sources: X, Y); our internal baseline is 6 days." *(matched to a CFO's lens, sources named, gap acknowledged where present)*

**Objection handling**
- Weak: (objections not mentioned) → the meeting stalls on the first "what about data risk?"
- Strong: "Anticipated objection — data risk: pilot uses only de-identified data in a walled environment; no production integration until gate 2."

**Whole artifact**
- Weak: a polished 15-slide deck that never states what leadership must decide. Fails gate 3, 13, 14 — high effort, low outcome probability.
- Strong: a one-page decision memo with the ask in the first two lines, three objections pre-empted, and a named sponsor path. Less content, far higher outcome probability.
