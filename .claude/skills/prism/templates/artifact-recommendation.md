# Template — Artifact Recommendation

State the recommendation clearly and defend it against the format the user asked for. Lead with the answer.

## Instructions
- Use the decision logic in `SKILL.md` and the details in `references/artifact-types.md`.
- Always contrast against the default/requested artifact — the value of PRISM is visible only when you show why the obvious choice is worse.
- Recommend a primary and, where useful, a secondary artifact (e.g. memo to get the yes + presentation for the meeting).

## Structure

```
## Recommended Artifact

**Primary:** <artifact> — <one-line what it is>
**Secondary (if any):** <artifact> — <when it's used>

**Why this artifact:** <ties directly to the required outcome/decision and audience state — 2–4 lines>

**Why not the requested/default artifact (<e.g. a deck>):**
<what the default optimises for vs what this outcome needs; what would go wrong if we built the default — 2–4 lines>

**How this raises the probability of the outcome:** <the mechanism — e.g. forces a bounded ask, pre-empts the blocking objection, survives a 60-second skim>
```
